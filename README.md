# SimpleBankApplication

A simple RESTful banking/customer management API built with **Java and Spring Boot**.

This project is being built as a learning project to develop practical backend engineering skills, with a focus on REST APIs, application architecture, exception handling, persistence, testing, and eventually PostgreSQL/JPA.

## Current Tech Stack

* Java
* Spring Boot
* Spring Web
* Maven
* Git & GitHub
* HashMap (temporary in-memory persistence)
* HTTP/REST
* IntelliJ IDEA

> **Note:** The application currently uses an in-memory `HashMap` for data storage. PostgreSQL + JPA/Hibernate will be introduced in the next development phase.

---

## Architecture

The application currently follows a basic layered backend architecture:

```text
HTTP Request
     ↓
Controller
     ↓
Service
     ↓
HashMap
```

### Controller

Responsible for handling HTTP requests and routing them to the appropriate service methods.

### Service

Contains the application's business logic, including:

* Customer creation
* Customer lookup
* Customer updates
* Partial customer updates
* Customer deletion
* Duplicate email validation
* Customer ID generation

### Exception Handling

Custom exceptions are handled centrally using `@RestControllerAdvice`.

---

## Customer Model

Each customer contains:

```text
id
name
email
```

Customer IDs are generated by the application when a customer is created.

# API Endpoints

Base URL:

```text
/customers
```

## Create Customer

### `POST /customers`

Creates a new customer.

### Request

```json
{
  "name": "John Doe",
  "email": "john.doe@example.com"
}
```

The application generates the customer ID.

---

## Get All Customers

### `GET /customers`

Returns all customers currently stored in memory.

---

## Get Customer by ID

### `GET /customers/{id}`

Returns a specific customer.

Example:

```text
GET /customers/1
```

---

## Replace Customer

### `PUT /customers/{id}`

Replaces the existing customer representation for the specified ID.

Example:

```text
PUT /customers/1
```

```json
{
  "name": "Jane Doe",
  "email": "jane.doe@example.com"
}
```

The ID is controlled by the URL rather than the request body.

If the specified customer does not exist, the API returns `404 Not Found`.

---

## Partially Update Customer

### `PATCH /customers/{id}`

Updates only the fields supplied in the request.

Example:

```text
PATCH /customers/1
```

```json
{
  "name": "Jane Doe"
}
```

The customer's email remains unchanged.

Another example:

```json
{
  "email": "jane.doe@example.com"
}
```

Only the email is updated.

Fields that are not supplied remain unchanged.

---

## Delete Customer

### `DELETE /customers/{id}`

Deletes a specific customer.

Example:

```text
DELETE /customers/1
```

Returns:

```text
204 No Content
```

---

## Delete All Customers

### `DELETE /customers`

Deletes all customers currently stored in memory.

---

# Error Handling

The application uses custom exceptions and centralized exception handling.

### Customer Not Found

If a requested customer does not exist:

```text
404 Not Found
```

Example response:

```text
Customer with ID: 10 does not exist...
```

### Duplicate Customer Email

If an attempt is made to create a customer using an email that already exists:

```text
409 Conflict
```

# Testing

The API has been manually tested using IntelliJ IDEA's HTTP Client through a `requests.http` file.

The following operations have been tested:

* Creating customers
* Retrieving all customers
* Retrieving customers by ID
* Updating customers with PUT
* Partially updating customers with PATCH
* Deleting customers
* Deleting all customers
* Handling nonexistent customer IDs
* Duplicate email validation
* Confirming that PATCH does not overwrite unspecified fields
* Confirming that a customer ID supplied in a PATCH body does not change the resource ID

These are currently **manual HTTP/API tests**. Automated unit and integration tests will be added as the project develops.
